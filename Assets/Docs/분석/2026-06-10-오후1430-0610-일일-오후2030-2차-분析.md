## 1. 스테이지 BGM — 호출 순서

### 문제

`stage_data.json`의 `bgmIndex`와 무관하게 항상 0번 곡이 재생됨.

### 호출 그래프 (수정 전)

```text
GameScene 로드
  └─ AudioManager.OnSceneLoaded / Start
       └─ PlayBGMForScene("GameScene")
            └─ PlayGameBGM() → PlayStageBgm(0)   ← 항상 0번

(나중에) StageManager.LoadStage
  └─ PlayStageBgm(bgmIndex)   ← 의도한 경로이나 이미 0번 재생됨
```

### 부가 원인

Splash 등에서 먼저 생성된 `AudioManager`가 `stageBgmClips` 없이 싱글톤이 되면, `PlayStageBgm(n)`이 `gameBGM`(0번과 동일 clip)으로 fallback.

### 수정 후 소유권

| 시점 | 주체 | 동작 |
|------|------|------|
| `GameScene` 로드 | `AudioManager` | BGM **재생 안 함** |
| `StageManager.LoadStage` | `AudioManager.PlayStageBgm(bgmIndex)` | 스테이지별 곡 |
| 중복 Instance 파괴 | `CopyStageBgmClipsIfNeeded` | `stageBgmClips` 병합 |
| `StageManager` 없음 | `PlayGameBGM()` | fallback만 |

## 2. GuideTxt / WarningTxt — 팝업 레이어

### Hierarchy (GameScene)

```text
GuideTxt (CanvasGroup)
├── bg0          ← Short (≤16자)
├── bg1          ← Long  (>16자, Z/X 안내)
└── guide_text

WarningTxt
├── WarningLabel
├── Bg
└── WarningMsg
```

### 이중 테두리 원인

`bg0`/`bg1` **루트 Image**와 자식 `bg (1~3)`(동일 스프라이트)을 동시에 ON → 2~3겹 테두리.

### 단일 진입점 (수정 후)

`GuideTxt.ApplyPopup(Hidden | Short | Long)`:

- `Short` → `bg0` ON, `bg1` OFF, 자식 `bg (1~3)` **항상 OFF**
- `Long` → `bg1` ON, `bg0` OFF, 자식 OFF
- `StopAllCoroutines()` — 아이템 선택 힌트와 인트로 가이드 겹침 방지

`WarningTxt.SetPopupVisible` — `Bg` + `WarningLabel` + `WarningMsg` 동시 제어.

## 3. 가스(D) 사망 — 밸브 ↔ Die 애니 충돌 (핵심)

### 증상

가스+가스밸브 접촉 중 방호복 0 → **`밸브 → Die(~1초) → 밸브 → 사라짐`** 반복.

### Animator 트리거

| 트리거 | 클립 | 역할 |
|--------|------|------|
| `Valve` | `Player_Valve` | D + GasValve 정답 접촉 |
| `Die` | `Player_Die` | `StartDeathSequence` |

`SetValveAnimActive(true)`는 `anim.ResetTrigger("Die")` 후 `SetTrigger("Valve")` — Die와 **상호 배타**.

### 1차 버그 — FixedUpdate 프레임 순서

```text
Pollutant.FixedUpdate (접촉 중, TypeD, GasValve 정답)
  │
  ├─ [버그 경로] ApplyPlayerContactDamage
  │     ├─ player.ApplyPollutantDamage(dps)  → curProtection 0
  │     │     └─ StartDeathSequence
  │     │           SetState(Die)
  │     │           valveAnimActive = false (bool만, SetValveAnimActive 미호출)
  │     └─ (아직 살아있다고 판단) SetValveAnimActive(true)
  │           ResetTrigger("Die")  ← Die 취소
  │           SetTrigger("Valve")  ← 밸브 재진입
  │
  └─ 또는 FixedUpdate 초반에 valve ON 후 데미지 적용
```

`SetValveAnimActive(false)`의 early return:

```csharp
if (currentState == PlayerState.Die)
    return;  // ResetTrigger("Valve") 미실행
```

`StartDeathSequence`가 bool만 false로 두면 `SetValveAnimActive(false)`가 **no-op** → Valve 트리거 잔류.

### 2차 수정 포인트

**Player.cs**

- `StartDeathSequence`: `SetState(Die)` **후** `SetValveAnimActive(false)` 호출
- `SetValveAnimActive(true)`: `Die` 상태 · `IsGameOverPending` · `GameEnded`면 **return**
- `SetValveAnimActive(false)`: Die 상태에서도 `ResetTrigger("Valve")` 실행

**Pollutant.cs**

- `ApplyPollutantDamage` **이후**에만 `SetValveAnimActive(valveOn)` (사망 시 valveOn 경로 차단)
- `CanProcessPlayerContact`: `IsGameOverPending` 추가
- `FixedUpdate` / `ApplyPlayerContactDamage`: 사망·게임 종료 시 TypeD `SetValveAnimActive(false)` + `HideBars`

### 수정 후 사망 프레임 (의도)

```text
ApplyPollutantDamage → StartDeathSequence
  SetState(Die)
  SetValveAnimActive(false)   ← Valve 트리거 정리
  BeginPlayerDeathSequence → HidePollutantHpBar

이후 FixedUpdate:
  CanProcessPlayerContact == false
  SetValveAnimActive(false)   ← 재호출 안전
  (SetValveAnimActive(true) 경로 없음)
```

## 4. 게임오버 패널 — 타임라인

### 문제 (1차)

`dieAnimDelay`(2s) 후 **패널과 플레이어 페이드가 동시** 시작.

### 원인

| 코루틴 | 대기 | 다음 동작 |
|--------|------|-----------|
| `ShowGameOverPanelAfterDeathAnim` | `dieAnimDelay` | 패널 표시 |
| `DieAndFadeOutRoutine` | `dieAnimDelay` | `FadeAlphaTo(0)` |

둘 다 T=2s에 시작 → Die 포즈와 패널 겹침.

### 수정 후 (2차)

```text
T=0s     StartDeathSequence · Die 트리거
T=2s     dieAnimDelay — Player 페이드 시작 (dieFadeDuration 기본 0.5s)
T=2.5s   페이드 완료
T=3.5s   diePanelDelayAfterFade(1s) 후 GameOverSet + SFX
```

`GameManager`: 패널 = `dieAnimDelay` + `player.dieFadeDuration` + `diePanelDelayAfterFade`.
