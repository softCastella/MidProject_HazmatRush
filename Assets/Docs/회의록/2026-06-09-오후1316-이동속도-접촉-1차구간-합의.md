## 3. 플레이어·배경 속도 합의

### 3.1 방식 · 단위

| 항목 | 내용 |
|------|------|
| 배경 이동 방식 | **오프셋 스크롤** — `Background.cs`에서 `offsetX` 누적 → `SetTextureOffset` (단일 텍스처 UV 이동) |
| 패럴랙스 | **사용 안 함** — 여러 레이어 다른 속도가 아님 |
| `Player.moveSpeed` | 월드 X 유닛/초 |
| `Background.scrollSpeed` | UV 오프셋/초 (0~1 범위, 메시 가로 1920) |
| 배경 체감 속도 | `scrollSpeed × 1920` 유닛/초 |

### 3.2 동기화 참고 (오프셋 스크롤)

```text
scrollSpeed ≈ moveSpeed / 1920   ← 플레이어와 1:1 맞출 때
```

| moveSpeed | 1:1 참고 scrollSpeed |
|-----------|----------------------|
| 400 | ≈ 0.208 |
| 300 | ≈ 0.156 |

### 3.3 현재 GameScene 값

| 항목 | 값 |
|------|-----|
| `moveSpeed` | **400** (최소 300 이상 체감 요청 반영) |
| `scrollSpeed` | **0.2** (오프셋 스크롤 · 실플레이 체감 확정, 1:1에 근접) |

- **금지:** `moveSpeed`만 낮추고 `scrollSpeed` 유지 — 상대적으로 배경만 빨라짐.
- 속도 변경 시 **Inspector에서 둘을 함께** 조정.

## 4. 접촉 판정 (A~C / D 동일 유지)

### 4.1 원칙 (기존 회의록 §4 유지)

- 데미지: `OnTriggerStay2D` → `ApplyPlayerContactDamage`만.
- D만 `Update` bounds 분기 **금지**.
- 접촉 해제: `EndPlayerContact` → HP `pollutanMaxHp` 초기화.

### 4.2 고속 이동 보완 (2026-06-09 추가)

| 조치 | 내용 |
|------|------|
| 이동 타이밍 | `Player` 실제 이동 **`FixedUpdate`** (물리와 동기) |
| 트리거 스킵 보정 | `Pollutant.LateUpdate` — Stay가 빠진 프레임에 bounds 겹치면 데미지 1회 보정 |
| Exit 오판 방지 | `GetContactOverlapPadding` — `moveSpeed × fixedDeltaTime` + 플레이어 콜라이더 여유 |

- 보정 경로도 `ApplyPlayerContactDamage` **동일 호출** — A~C/D 이원화 없음.

## 8. App 씬 진입점·서버 확장 검토 (구현 전 합의)

> 클라이언트 단독 플레이 기준. 추후 서버·멀티 연동을 위해 **앱 전체 수명주기**를 한곳에서 관리하는 `AppScene` 도입 방향 검토.  
> **당일 미구현** — PR 단위로 분리해 진행.

### 8.1 배경·현재 구조

| 항목 | 현재 |
|------|------|
| Build 첫 씬 | `SplashScene` |
| 씬 흐름 | Splash → Title → Intro → Loading → Game |
| `DontDestroyOnLoad` | `SceneLoadManager`, `AudioManager` |
| 씬별 매니저 | Title / Game / Intro / Splash 등에 **동일 매니저 중복 배치** (싱글톤으로 첫 인스턴스만 유지) |
| 게임플레이 | `GameManager`·`Player`·`Pollutant` — `GameScene` 전용 |

- `SceneLoadManager.LoadScene` — 싱글 씬 로드 (`Time.timeScale = 1` 리셋 포함).
- `SplashController`·`TitleSceneFade`·`LoadingController` — 일부 경로에서 `SceneManager.LoadScene(Async)` **직접 호출**.

### 8.2 App 씬 역할 (역할 분리)

```text
AppScene (항상 살아 있음 · Build Index 0)
├── AppBootstrap / AppController   ← 앱 시작·종료·버전·(나중) 서버 연결
├── SceneLoadManager
├── AudioManager
└── (미래) NetworkManager, AuthService, SessionState

Content Scenes (로드될 때마다 교체)
├── SplashScene   ← 연출만
├── TitleScene    ← UI만
├── LoadingScene
└── GameScene     ← GameManager, Player, Pollutant 등
```

- **App 씬 = 게임 앱**, **나머지 = 화면·스테이지**.
- `GameManager`는 **App으로 옮기지 않음** — `GameScene`에 유지 (접촉·이동 단일 모델 §4와 분리).

### 8.3 단계별 진행 (PR 분리)

| PR | 내용 | 위험도 |
|----|------|--------|
| **PR1** | `AppScene` + `AppBootstrap` + Build Settings index 0 · 싱글 `LoadScene` 유지 | 낮음 |
| **PR2** | Title/Game/Splash/Intro **중복** `SceneLoadManager`·`AudioManager` 제거 · App Inspector에 클립·`stageBgmClips` 통합 | 중간 |
| **PR3** | Additive 로딩 + `activeScene` 설정 + 콘텐츠 씬 unload | 높음 |
| **PR4** | (미래) 서버·세션·로그인 — App 레이어만 | 별도 |

#### PR1 상세 (당장 적용 가능)

1. `Assets/Scenes/AppScene.unity` — `SceneLoadManager`, `AudioManager`만 배치.
2. `AppBootstrap.cs` — `Start`에서 `SceneLoadManager.Instance.LoadScene("SplashScene")`.
3. Build Settings: `AppScene` = index 0, 기존 5씬 유지.
4. 기존 씬의 중복 매니저는 **당장 제거하지 않아도** App이 먼저 생성되면 동작 유사 (점진 정리).

#### PR3 — Additive (서버 붙이기 전 권장)

- App은 항상 로드, 콘텐츠만 Additive 교체.
- `SceneLoadManager`에 `UnloadSceneAsync` + `LoadSceneAsync(..., Additive)` + **활성 씬 지정** 필요.
- 싱글 로드만 쓰면 App 씬은 unload되나 `DontDestroyOnLoad` 매니저는 유지 — PR1은 이 방식으로 충분.

### 8.4 서버 연동 시 App vs GameScene

| App 레이어 (씬 전환해도 유지) | GameScene (플레이 세션) |
|------------------------------|-------------------------|
| 로그인·토큰·재접속 | `Player`, `Pollutant`, `GameManager` |
| 매치메이킹·방 입장 | 스테이지 진행·클리어/게임오버 |
| ping·disconnect | 입력·HP·오염원 판정 (권한 모델은 별도 설계) |

```text
AppBootstrap → (미래) ConnectToServer → Splash / Title
Title "시작" → App: RequestStartSession → Loading → Game
클리어/게임오버 → GameManager 결과 → App: Save + Title 복귀
```

- `GameSaveManager`는 static — App 레이어와 잘 맞음. 서버 저장 시 App에서 로컬/서버 분기만 추가.

### 8.5 버그 위험 (검토 결론)

| 단계 | 위험 | 비고 |
|------|------|------|
| PR1 App + 싱글 로드 | **낮음** | 기존 `DontDestroyOnLoad` 패턴의 진입점만 앞당김 |
| 중복 매니저 미정리 | 중간 | App `AudioManager` 클립·`stageBgmClips` 누락 시 무음/스테이지 BGM 누락 |
| Additive 로딩 | **높음** | 활성 씬·Camera·AudioListener·EventSystem 중복 |
| gameplay를 App으로 이전 | **매우 높음** | §4 접촉 단일 모델 회귀 — **금지** |

**합의:** App 씬 도입 자체는 안전. **Additive·서버·매니저 정리를 한 PR에 묶지 않기.**
