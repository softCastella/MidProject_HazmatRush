## 1. 배경

- 오염원 **Type D(가스)** 추가 및 관련 로직 삽입 이후, **플레이어 이동·콜라이더·오염원 스폰·접촉**에서 버그가 재발.
- 이전 최적화 이후에도 동일 영역(이동, 스폰, 접촉)이 가장 먼저 문제되는 패턴이 반복됨.
- 물리 구성: **Rigidbody2D는 플레이어만** 보유, 접촉 관련 오브젝트(오염원 포함)는 **Collider2D** 부착.

---

## 2. 현상·원인 정리 (합의)

### 2.1 복잡도가 높은 지점

| 구분 | 내용 |
|------|------|
| **Player** | 이동(`Update`) + 범위(`GrowRange`/`BlockPollutant`) + 통과 방지(`ClampPassThroughPollutants`) + 맵 전환 + 밸브 잠금 + 방호복 + VFX + 사망 코루틴이 한 클래스에 집중 (~720줄) |
| **Pollutant** | A~C는 `OnTriggerStay2D`, **D만 `Update` + bounds 겹침**으로 접촉 처리 (이원화) |
| **상태 분산** | `canMove`, `valveAnimActive`, `GameManager` 플래그, `PollutantManager` 맵 전환 플래그 등이 여러 객체에 분산 |

### 2.2 버그가 나기 쉬운 구조적 이유

1. **접촉 판정**은 트리거 겹침(`OnTriggerStay`)에 의존.
2. **이동 제한**은 코드 Clamp(`ClampPassThrough`, `leftLimit`/`rightLimit`)로 처리.
3. Clamp가 트리거 **진입 전**에 플레이어를 막으면 `OnTriggerEnter`/`Stay`가 끊김 → D는 `Update` 우회 경로 추가 → 복잡도·불일치 증가.
4. 오염원 D에도 **콜라이더는 이미 있음**. 문제는 콜라이더 부재가 아니라 **코드상 트리거 경로를 막고 별도 경로를 둔 것**.

### 2.3 코루틴에 대한 판단

- 사망·복귀·페이드 코루틴 자체보다 **`Update`에 몰린 이동·범위·통과 방지 분기**가 불안정성의 핵심.
- 코루틴은 상대적으로 모드 전환(복귀 중/사망 중)을 명시해 오히려 안전한 편.

## 3. 회의에서 정리한 방향 (합의안)

### 3.1 플레이어 이동·중화 로직 — **변경하지 않음** (우선 원칙)

- `MovePosition`, `ClampPassThroughPollutants`, `leftLimit`/`rightLimit`, `SetValveAnimActive`, `ApplyPollutantDamage` 등 **핵심 이동·중화 동작은 고정**.
- 버그 수정·구조 정리는 **오염원(`Pollutant.cs`) 쪽 접촉 경로 통일**을 우선으로 진행.
- Player를 건드릴 경우에도 이동 공식 변경이 아닌, **접촉 안 될 때만 `ClampPassThrough` 조건 검토** 수준으로 제한.

### 3.2 오염원 D — **A~C와 동일한 트리거·HP 로직으로 통일** (1순위 작업)

| 현재 (D만 다름) | 변경 후 (A~C와 동일) |
|----------------|---------------------|
| `OnTriggerStay2D`에서 D early return | 모든 타입 `OnTriggerStay2D` → `ApplyPlayerContactDamage` |
| `Update` + `IsBoundsOverlappingPlayer` | **삭제** |
| 접촉 해제 시 HP **유지** | 접촉 해제 시 HP **`pollutanMaxHp` 초기화** + `RegisterPollutantReset` |

**유지하는 D 전용 요소** (연출·규칙, 접촉 경로와 무관):

- 가스밸브 애니 (`SetValveAnimActive`)
- 밸브 SFX (`squeakyValveSFX`) — A~C 중화 루프음과 분리
- 파티클 비주얼
- `PollutantManager`의 D 별도 스폰 타이머, A~C와 동시 존재 가능

**게임 규칙 변경 사항:** README에 있던 “가스(D) 접촉 해제 시 HP 유지”는 **“접촉 해제 시 HP 초기화”**로 변경. 구현 후 README·AGENTS 동기화 필요.

**수정 범위:** 주로 `Pollutant.cs` (Player 무변경 목표).

### 3.3 벽 콜라이더(Solid) — **사용하지 않음**

- `MovePosition` + Solid 충돌 시 물리 되밀림과 Clamp가 겹쳐 **부들부들 떨림** 발생.
- 통과 방지는 기존 **`ClampPassThroughPollutants`(한 프레임 관통만 차단)** + 트리거 조합 유지.

### 3.4 Player 로직 분리 — **보류 (2순위, 선택)**

| 판단 | 내용 |
|------|------|
| 일반적인가? | 연출·UI만 분리하는 것은 업계에서 흔함. **이동까지 분리하는 것은 현재 규모에 과함.** |
| 지금 필수인가? | **아님.** D 접촉 통일이 효과·우선순위 모두 더 큼. |
| 나눈다면 | **이동은 `Player.cs`에 유지.** VFX·사망 페이드·방호복 UI만 분리 후보. |
| 규칙과 맞는 최소안 | 새 클래스 없이 `#region` 정리, 또는 컴포넌트 1개(`PlayerPresentation` 등) |

## 4. 접촉 판정 규칙 (표준) — **코드 수정 전 필수 합의**

> D=A~C 통일만으로는 부족할 수 있음 (`2026-06-04-시각미상-gameplay-fixes.md` 참고).  
> **아래 규칙을 깨는 패치는 구현 전에 영향 검토·사용자 확인 후 진행.**

### 4.1 전제

| 항목 | 내용 |
|------|------|
| 물리 | **Rigidbody2D = 플레이어만.** 오염원·기타 = `Collider2D`(Trigger) |
| A~C / D | **접촉·HP 초기화·데미지 경로 동일.** D만 연출·스폰 규칙이 다름 |
| HP | 접촉 해제 시 `pollutanCurHp = pollutanMaxHp` + `RegisterPollutantReset` (가스 포함) |
| 벽 | Solid 콜라이더 **사용 안 함** (MovePosition + 물리 되밀림 → 떨림) |

### 4.2 역할 분리 (한 객체가 두 역할 하지 않기)

| 담당 | 역할 |
|------|------|
| **Player** | 이동(`MovePosition`), `leftLimit`/`rightLimit`, `ClampPassThroughPollutants` |
| **Pollutant** | 접촉 판정, `ApplyPlayerContactDamage`, HP, 접촉 해제 |
| **D 연출만** | `SetValveAnimActive`(애니·SFX), 파티클 비주얼 — **접촉 판정과 분리** |

**플레이어 이동·중화 공식은 회의 합의대로 무분별 변경 금지.**  
Player 수정은 `ClampPassThrough` 조건 보완 등 **접촉 보조** 수준만 허용.

### 4.3 접촉 판정 — 단일 모델 (`Pollutant.cs`)

```text
OnTriggerEnter2D
  → currentPlayer 설정, HP바, AddPollutantTouch

OnTriggerStay2D
  → currentPlayer 갱신만 (데미지 호출 금지 — FixedUpdate와 중복 방지)

FixedUpdate
  → currentPlayer 있고 IsPlayerInContact() 이면 ApplyPlayerContactDamage (데미지는 여기만)

OnTriggerExit2D
  → strict bounds(여유 0) 겹치면 Exit 무시(오판 방지)
  → 아니면 EndPlayerContact()

EndPlayerContact()
  → 밸브 off, RemovePollutantTouch, HP 초기화, 슬라이더 숨김, currentPlayer = null
```

**`IsPlayerInContact()`**

1. `pollutantCol.bounds` ∩ `playerCol.bounds` → 접촉
2. 가스(D) + `IsValveAnimActive`일 때만 **padding 0.15f** 보조 (애니로 bounds 잠깐 어긋남)
3. **금지:** `IsValveAnimActive`만으로 무조건 접촉 true — 이동·해제 불가 버그 원인

### 4.4 데미지·판정 순서 (`ApplyPlayerContactDamage` — A~C/D 동일)

1. 아이템 판정 로그 (`올바른/틀린 아이템`)
2. `player.ApplyPollutantDamage(pollutanDps)` — 방호복 감소
3. **추천 == 선택**일 때만 오염원 HP 감소 (`itemDps * Time.fixedDeltaTime`)

### 4.5 D(가스) 전용 연출 (접촉 규칙과 분리)

| 항목 | 규칙 |
|------|------|
| 밸브 애니·SFX | 정답(가스밸브) + 접촉 중 `SetValveAnimActive(true)` |
| **이동** | 밸브 중에도 **이동 허용** — `Player.Update`에서 `valveAnimActive`로 return **금지** |
| 중화 VFX | 가스(D) 접촉 중 **CFXR 중화 이펙트 사용 안 함** (`RefreshNeutralizationVfx` 호출 안 함) |
| 중화 루프 SFX | A~C만. D는 밸브 SFX만 |
| 페이드아웃 | HP 0 시 emission 즉시 중단 → 알파 페이드 → `StopEmittingAndClear` |

### 4.6 Player `ClampPassThrough` 보조 규칙

- **이미 bounds가 겹치는** 오염원에는 통과 방지 적용 **안 함** (트리거 진입·유지 보조)
- 한 프레임에 오염원 **전체를 가로지를 때만** 막기 (기존 의도 유지)

### 4.7 금지 목록 (재발 방지)

- D만 `Update()` / bounds 우회 / `OnTriggerStay` early return — **A~C와 이원화 금지**
- `IsEdgeContact` 재활성화
- 밸브 on = 무조건 접촉 유지
- 밸브 on 시 플레이어 이동 잠금
- 가스 접촉 해제 시 HP 유지 (README 구규칙 — **초기화로 통일**)
- 증상별 패치를 **사전 검토 없이** 연쇄 추가

## 6. 리스크·주의사항

1. D 통일 후에도 접촉 불가 시 → 원인은 D가 아니라 **`ClampPassThroughPollutants`가 트리거 진입을 막는지** 재확인. Player 이동 공식 변경은 최후 수단.
2. `FindObjectsByType<Pollutant>()` (이동 시 매 프레임) — 당장 필수 수정은 아니나, 장기적으로 `PollutantManager` 활성 목록 캐시 검토 가능.
3. `IsEdgeContact` — `Pollutant.cs`에 잔존하나 **미사용**. 재활성화 금지 (과거 접촉 끊김 원인).
