# AI 협업 운영 방식 (1인 · 바이브코딩)

| **최초작성** | 2026-06-15 · 시각미상 |
| **대상** | Hazmat Rush (MidProject) · 1인 팀 · Cursor AI 보조 개발 |
| **관련** | [AGENTS.md](../../AGENTS.md) · [.cursor/rules/](../../.cursor/rules/) · [회의록 §4](회의록/2026-06-05-시각미상-플레이어-오염원-로직-검토.md) · [gameplay-fixes](Bug/2026-06-04-시각미상-gameplay-fixes.md) · [클리어·VFX-fixes](Bug/2026-06-05-시각미상-클리어-가이드-중화VFX-fixes.md) |

1인 팀에서 Cursor AI로 **바이브코딩**할 때, “AI에게 맡기되 **게임 규칙·Git·문서는 통제**”하기 위해 쓰는 운영 방식입니다.  
발표·포트폴리오에서 **구체 사례**로 설명할 수 있도록, 실제로 터졌던 문제와 rules/AGENTS 활용을 묶어 정리했습니다.

---

## 1. 왜 이렇게 나눴는가

| 문제 | 대응 |
|------|------|
| 1인이라 코드·문서·QA·발표를 혼자 처리 | AI에 반복·초안·패치를 맡기고, **규칙은 문서로 고정** |
| “접촉만 고쳐줘” 한 마디에 **VFX·Git·아이템 초기화**까지 같이 바뀜 | **깨지면 QA에서 바로 터지는 것**만 `.cursor/rules`에 짧게 박음 |
| rules만 있으면 **왜** 그런지 모름 | **회의록·Bug**에 합의·증상·해결 기록 (정본) |
| AI·사람 모두 프로젝트 진입점 필요 | **AGENTS.md** — 온보딩·파일 맵·체크리스트 |

**중복이 아니라 역할 분리**입니다.

```text
[사람] 요청 · Play 테스트 · 합의
    ↓
[.cursor/rules]  ← Cursor가 자동 주입 (짧은 금지·체크)
    ↓
[AGENTS.md]      ← 온보딩·어디를 볼지
    ↓
[회의록 / Bug]   ← 게임플레이·버그의 정본 (의도·이력)
    ↓
[코드]           ← Pollutant.cs, Player.cs …
```

---

## 2. 파일별 역할

### AGENTS.md

- **누가:** 사람 + AI 공통 진입 문서
- **내용:** 프로젝트 요약, 코딩 원칙, 금지 목록, Hierarchy·테스트 체크리스트, rules 목록
- **비유:** 팀 온보딩 PDF + “수정 전에 볼 파일 표”

### `.cursor/rules/` (4개)

| 파일 | 적용 시점 | 하는 일 |
|------|-----------|---------|
| `midproject-core.mdc` | **항상** | 단순 코드, 최소 diff, Git 금지, 접촉·VFX 한 줄 요약 |
| `git-worktree-workflow.mdc` | **항상** | master·브랜치·worktree·PR (AI가 임의 checkout/push 안 함) |
| `unity-gameplay.mdc` | `Assets/Scripts/**/*.cs` | HP, OnTriggerStay 단일 경로, VFX, Clear/Die 2초 |
| `docs-harness.mdc` | `Assets/Docs/**` | Bug/회의록 분리, 당일 취합, 파일명 규칙 |

- **누가:** Cursor가 채팅·편집 시 **자동**으로 컨텍스트에 넣음
- **비유:** 린터 + “절대 하지 마” 스티커 (짧게)

### 회의록 · Bug

- **회의록:** *왜* 이렇게 동작해야 하는지 (합의, 금지, 체크리스트)
- **Bug:** *무엇이* 터졌고 *어떻게* 고쳤는지 (증상, 원인, 파일)
- **AI 수정 전:** Player/Pollutant 건드릴 때 rules가 **이 문서 읽기**를 요구

## 3. 실전 예시 — rules/AGENTS를 **어디에** 썼는지

### 예시 A · 틀린 아이템인데 중화 VFX가 켜짐

**상황**  
접촉 판정(방호복 감소·오염원 HP)은 맞는데, **추천과 다른 중화 도구**로 닿아도 CFXR 파티클이 재생됨.

**AI가 하기 쉬운 잘못된 패치**  
`RefreshNeutralizationVfx()`를 “스캐너가 아니면 ON”처럼 **단순화** → 오답 접촉에도 VFX ON.

**rules/AGENTS로 고정한 규칙**

- VFX ON: 접촉 중 **A~C** + `IsSelectedItemRecommendedFor(pollutant)` == true
- VFX OFF: 스캐너, **틀린 도구**, **가스(D)**, 밸브 연출 중
- `unity-gameplay.mdc` · AGENTS §2 **하지 말 것**에 동일 문구

**정본·이력**  
[클리어·VFX-fixes §5](Bug/2026-06-05-시각미상-클리어-가이드-중화VFX-fixes.md) · [회의록 §4](회의록/2026-06-05-시각미상-플레이어-오염원-로직-검토.md)

**발표 한 줄**  
> “중화 VFX 수정 요청할 때 AI가 조건을 줄이려 해서, rules에 **정답 A~C만 VFX**를 박아 회귀를 막았습니다.”

---

### 예시 B · 접촉 데미지가 고속 이동·가스에서 끊김

**상황**  
플레이어가 빠르게 이동하거나 가스(D) 옆 A~C에 접근할 때 HP·판정이 **끊기거나** 가스 HP가 중간에서 멈춤.

**AI가 하기 쉬운 잘못된 패치**

- `IsEdgeContact` 조건 **다시 켜기** → Stay 데미지 누락
- 가스(D)만 `Update` / `OnTriggerStay` **early return** → A~C와 **접촉 경로 이원화**
- Solid 벽 콜라이더로 **통과 방지** → 떨림

**rules/AGENTS로 고정한 규칙**

- A~C / D **동일 경로:** `OnTriggerStay2D` → `ApplyPlayerContactDamage` (데미지는 여기만)
- D는 **연출만** 분기 (밸브 애니·SFX, VFX 없음)
- 위 금지 항목을 `unity-gameplay.mdc` **금지** 섹션 + AGENTS **하지 말 것**에 명시

**정본·이력**  
[gameplay-fixes](Bug/2026-06-04-시각미상-gameplay-fixes.md) · 회의록 §4.8 체크리스트

**발표 한 줄**  
> “접촉 버그 패치할 때마다 AI가 **D만 예외 처리**하거나 **IsEdgeContact**를 되살리려 해서, **단일 OnTriggerStay 모델**을 rules에 고정했습니다.”

---

### 예시 C · 오염원 제거 후 아이템이 중화제로 초기화

**상황**  
맵에서 오염원 1기 중화 후, 플레이어가 고른 패드/중화제가 **스캐너·중화제로 리셋**됨.

**AI가 하기 쉬운 잘못된 패치**  
오염원 HP 0일 때 `ItemSelectManager.ResetToDefault()` **다시 추가** (“다음 경고 대비”).

**rules/AGENTS로 고정한 규칙**

- 오염원 제거 시 `ResetToDefault()` **호출 금지**
- `OnWarningShown()`: **첫 경고만** 중화제 기본, 이후 선택 유지
- 스테이지 리셋(`ResetForStage`) 때만 Scanner 초기화

**정본·이력**  
[클리어·VFX-fixes §3](Bug/2026-06-05-시각미상-클리어-가이드-중화VFX-fixes.md)

**발표 한 줄**  
> “클리어 직후 UX를 ‘정리’하려고 AI가 **ResetToDefault**를 넣으려 할 때, rules **금지**로 막았습니다.”

---

### 예시 D · 프리팹 꼬였을 때 AI가 git restore 제안

**상황**  
씬·프리팹 YAML이 꼬이면 AI가 **`git checkout` / `git restore`** 로 되돌리자고 제안하는 경우가 많음.

**rules/AGENTS로 고정한 규칙**

- Git 명령은 **사용자가 명시적으로 요청할 때만** (`commit`, `restore`, `status` 포함)
- 되돌리기도 git 금지 → **파일 직접 수정** 또는 사용자 확인
- worktree·PR 절차는 `git-worktree-workflow.mdc` · [Git workflow](2026-06-08-시각미상-git-workflow-worktree.md)

**발표 한 줄**  
> “1인이라 실수하면 바로 망가지니, AI에게 **Git은 내가 시킬 때만** 쓰게 rules로 막았습니다.”

---

### 예시 E · 문서·코드 변수명 불일치 (`pollutan*` → `pollutant*`)

**상황**  
코드에서 오타 변수명을 `pollutantCurHp` 등으로 정리한 뒤, **AGENTS·rules**에는 옛 이름(`pollutan*`)이 남아 있음.

**왜 문제인가**  
다음 AI 요청 때 **엉뚱한 필드명**으로 패치하거나, Inspector `[FormerlySerializedAs]`와 혼동.

**한 일**  
`Pollutant.cs` 리네임 후 **AGENTS.md · midproject-core · unity-gameplay · README**를 같은 이름으로 동기화.

**발표 한 줄**  
> “바이브코딩은 **코드와 AI 가이드가 같은 이름**을 써야 해서, 변수명까지 문서에 맞춰 두었습니다.”

## 4. 평소 작업 흐름 (1인 + AI)

```text
1. Play 또는 QA로 증상 확인
2. 요청문 작성 (파일명 + 원하는 동작 + 재현)  ← AGENTS §5 예시 참고
3. Cursor가 rules 자동 적용
   · Scripts → unity-gameplay
   · Docs → docs-harness
   · 항상 → core + git-workflow
4. AI가 회의록/Bug 링크 있는 합의를 참고해 **최소 diff** 패치
5. 사람이 GameScene Play · §4.8 또는 Bug 체크리스트로 검증
6. 합의가 바뀌면 회의록/Bug 갱신 → rules는 **한 줄 요약만** 유지
```

**요청문 좋은 예 (AGENTS에서 가져옴)**

```text
Pollutant.cs에서 접촉 중 틀린 아이템일 때는 [Pollutant] HP 로그를 생략해줘.
Scanner로 GeneralPad 오염원에 닿았을 때 로그가 너무 많이 나와.
```

**나쁜 예**

```text
로그 고쳐줘
```

## 5. 발표·포트폴리오용 요약 (30~40초)

> Hazmat Rush는 **1인 팀 + Cursor 바이브코딩**입니다.  
> AI에게 구현을 맡기되, **접촉·중화 VFX·Git·문서 규칙**은 `.cursor/rules`에 짧게 고정하고,  
> **왜 그런지**는 회의록과 Bug에 남깁니다.  
> 예를 들어 **틀린 아이템 VFX**나 **가스만 접촉 로직 분리**처럼, AI가 자주 하려는 **증상 패치**는  
> rules와 [0604·0605 Bug](Bug/2026-06-04-시각미상-gameplay-fixes.md)로 막았고,  
> **AGENTS.md**는 온보딩과 파일 맵 역할입니다.  
> 그래서 1인이어도 **재현 가능한 AI 협업**으로 QA 7건 대부분을 통과할 수 있었습니다.

슬라이드 3줄 버전:

```text
Cursor + AGENTS.md + .cursor/rules (1인 바이브코딩)
예) 접촉·VFX → OnTriggerStay 단일 경로 / 정답 A~C만 VFX (0605 Bug §5)
예) Git → 사용자 요청 시에만 (midproject-core)
정본 → 회의록 §4 · Bug · README
```

## 6. 무엇을 rules에 넣고 무엇은 넣지 않는가

| rules에 넣음 | rules에 넣지 않음 (회의록/Bug/README) |
|--------------|--------------------------------------|
| **금지** (ResetToDefault, git restore, D 이원화) | 증상 재현·Console 로그 |
| **한 줄 동작** (Stay만 데미지, 2초 후 패널) | GrowRange·ClampPassThrough 같은 **해결 과정** |
| **읽을 문서 경로** | PR 번호·커밋 해시·스크린샷 |
| **변수·API 이름** (`pollutantCurHp`) | UI 배치·인스펙터 숫자 튜닝 |

rules가 길어지면 AI 컨텍스트만 비대해지므로, **“깨지면 QA 터지는 것”만** rules에 두고 나머지는 Bug/회의록으로 보냅니다.
